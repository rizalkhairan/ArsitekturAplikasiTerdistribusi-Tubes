# Problem 5 — The lying buoy

## 1. Problem identification

The Sensor Pantai image is a black box that emits observations with a weak
contract and several failure modes: silence, bursts, stale data behind a green
`/healthz`, malformed records, and state resets after a pod restart. The system
must keep critical alerts flowing, keep other sources fast, avoid hammering a
sick source, and degrade reads gracefully. Literature and patterns:

- **Circuit breaker** (Nygard, *Release It!*): closed/open/half-open, one probe.
- **Bulkhead**: isolate the sensor path (goroutine, bounded queue, breaker) from
  BMKG/PVMBG and the read path.
- **Timeout, retry, exponential backoff, full jitter, retry budget**: avoid retry
  storms and synchronized retries.
- **Load shedding / admission control** (SRE workbook): reject early with 429/503
  and `Retry-After` instead of queueing forever.
- **Graceful degradation**: last-known-good cache with `stale:true` + `as_of`.
- **Priority queueing / reserved capacity**: protect Tim Lapangan traffic.
- **Transactional outbox**: persist the critical alert before advancing the
  checkpoint; deliver at-least-once; receiver dedupes (effective-once).
- **Idempotence** and deterministic keys: retries and cursor fallback are safe.
- **Poison message / validation**: park invalid data in the DLQ with a reason.
- **Progress-based health**: do not trust `/healthz`; measure new, fresh
  observations.

## 2. Mechanisms and configuration

### 2.1 Sensor client

| Mechanism | Config | Rationale |
|---|---|---|
| Per-request timeout | 3 s | Sensor is local; a slow call is a symptom |
| Retry | up to 3 attempts, exponential backoff + **full jitter** | Avoid synchronized retries |
| Retry budget | 10 tokens, 0.2 tokens/s refill | Bounds retries relative to traffic |
| Breaker | trip at ≥50 % failures over ≥3 outcomes; slow calls ≥3 in window; staleness; 15 s open; one half-open probe | Stop request spikes; recover automatically |
| Progress health | `SENSOR_STALE_AFTER=45 s` since a **new** composite id | `/healthz` is not trusted |
| Last-known-good | in-memory per station | Fast degraded reads |
| Pagination | `limit=100`, max 20 pages, cursor | Bound burst work |
| Cursor fallback | on 400/409/422, re-read from start, keep `last_observed_at - 5 min` | Survive emptyDir reset |
| Dedupe | `station_id + observed_at + observation_id` | Ids may repeat after restart |
| Poll singleton | same lease/epoch as P2, source `SENSOR_PANTAI` | Three replicas never triple requests |

### 2.2 Validation and DLQ

Required fields and types; finite numbers; configurable plausible ranges
(sea-level anomaly ±10 m, wave 0–50 m); RFC3339 and UTC; not more than 5 min in
the future; `station_id` present in `/v1/stations`; `quality` in a configurable
enum; `critical` boolean. Failures are parked via `park(source, raw, reason,
retryable)` with reason codes `schema`, `field_type`, `non_finite`, `range`,
`timestamp`, `future_timestamp`, `unknown_station`, `quality`. Invalid data is
never mapped to a HazardEvent.

### 2.3 Bulkhead

The sensor poller is its own leader-elected goroutine with a bounded page loop
and a bounded DLQ queue (512, 4 workers). A stuck sensor cannot block the BMKG or
PVMBG pollers or the read API. Storage failure on the sensor path does not stop
the normal sources.

### 2.4 Priority lane

Critical observations are written to the coordinator **notification outbox before
the checkpoint advances**, independently of the normal storage path. Every
Aggregator replica runs a deliverer that claims entries with a 15 s lease,
POSTs to the field notifier with traceparent, and acks. Delivery is
at-least-once; the notifier dedupes by `dedupe_key` and records `received_at`.
If the poller dies mid-delivery, another replica claims after the lease.

### 2.5 Priority-aware admission control

The Client-Facing API validates the JWT first, derives `role=field` for
`field-user`/`internal-user` and `role=media` for `media-user`, then applies:

- field pool: `MAX_CONCURRENT_REQUESTS` (200 in k8s);
- media pool: `MAX_CONCURRENT_REQUESTS - RESERVED_FIELD_CAPACITY` (120 with 80
  reserved).

Media overflow returns `429` + `Retry-After: 1` with a structured error. Field
overflow is also controlled but has the reserved capacity. Every rejection is
counted as `admission_rejected_total{role,reason}`, so controlled rejections are
excluded from the SLO error calculation.

### 2.6 Read degradation

When the sensor is unhealthy, reads return the last-known-good snapshot with
`stale:true` and `as_of` immediately; `/sensor/status` exposes breaker state,
seconds since fresh, last observed/generated time, cache snapshot, and `as_of`.
If the shared storage is also unreachable, `/hazards?source=SENSOR_PANTAI` falls
back to the leader's last-known-good snapshot with `X-Data-Freshness: degraded`,
`X-Source-SENSOR_PANTAI-Status: stale`, and `Stale-Since`. A non-leader replica
uses the shared storage's latest sensor event for `as_of`. Recovery is automatic:
the half-open probe closes the breaker when new observations arrive.

## 4. SLO

**Primary SLO:** 99.5 % of critical sensor observations are delivered to the Tim
Lapangan notifier within **5 s**, measured over a rolling 24 h window.

- Error budget: 0.5 % of critical events may exceed 5 s.
- Hard invariant: **0 critical events lost** (outbox persisted before checkpoint;
  at-least-once delivery + receiver dedupe).
- Measurement: `critical_alert_pipeline_seconds` (from `dispatched_at` when the
  poller durably enqueues, to `received_at` at the notifier) for the SLO;
  `critical_alert_end_to_end_seconds` (from `observed_at`) is reported separately
  because a lying sensor can report an old observation time. Plus outbox depth and
  notifier `/stats`.
- Secondary SLOs: BMKG/PVMBG read p95 < 300 ms while the sensor is troubled;
  Tim Lapangan read availability ≥ 99 %.

Budget calculation:

```
budget_events = floor(critical_events_in_window * 0.005)
used_events   = count(critical_alert_end_to_end_seconds > 5s)
budget_used   = used_events / budget_events
```

## 8. Conscious limitations

- Sensor discovery was not executed here (no Docker/K8s). The `quality` enum,
  ranges, and severity thresholds are configurable assumptions until observed.
- The critical outbox is in the single coordinator (pinned to the control-plane).
  A control-plane loss stops delivery until it returns; entries are durable.
- The field-notifier stores receipts in memory. In production the receiver must be
  durable; the contract records receipt time for the SLO.
- The last-known-good cache is per Aggregator replica; a non-leader uses the
  shared storage for `as_of`, so reads remain consistent but the detailed
  snapshot may be empty on a non-leader.
- Media rejection is a controlled 429, not a hard guarantee that all field
  requests succeed; the reserved capacity is finite (by design).
